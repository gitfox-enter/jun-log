旧手机 + Nextcloud：我把吃灰安卓机改造成了私有云盘

2026年9月12日 · digital-life · #Nextcloud #NAS #旧手机改造 #自建服务 #动手实践

起因很简单：知乎刷到一个英文教程「Handheld-NAS」——用旧安卓手机 + Termux 搭私有云盘。我柜子里正好躺着一台退役的安卓机，于是决定：照着教程，把它变成一台真正的 NAS。

一、先说结论

折腾两天，最终成品：

  • Nextcloud 34.0.4 跑在一台旧手机上（proot Ubuntu 24.04，arm64）
  • 浏览器访问 http://127.0.0.1:8081，登录后就是一个完整私有云盘
  • 数据存在手机存储上，服务重启不丢数据（我特意停掉全部服务再拉起，验证了两次）
  • 数据库用 MariaDB（教程原版是 SQLite，我升级成了生产环境标配）

如果你只为”有个网盘”，其实百度网盘更省事。但这次折腾的意义不在网盘，在于把一条完整的自建服务链路亲手趟通了。

二、环境：从 ZeroTermux 换到 proot

教程原版用的是 Termux。我第一反应也是 ZeroTermux，但 API 连不上，换到资源更充足的 proot Ubuntu 24.04（14G 内存、678G 可用磁盘）——这一步很关键，后面装 PHP 扩展、跑 MariaDB 全靠它。

组件选型沿教程精神，但做了升级：

proot 环境的怪癖也踩了不少：没有 systemd（用 service）、没有 sudo（用 su -s /bin/bash www-data -c）、1024 以下端口绑不了（所以用 8081）。

三、最大的坑：277MB 下载了 3 个小时

教程要装 Nextcloud 官方包（277MB）。我以为几分钟的事，结果：

  • 官方源在德国，我这网络直连只有 15~40KB/s
  • 国内镜像全 404，FTP 不可用，分片并发被限速

折腾 3 小时无果，最后是靠本机代理（Karing，端口 4067）破局：16 线程并发，峰值 3MB/s，比直连快约 40 倍。1 分钟下完剩下的 49%。

四、差点翻车：aria2 的”假下载”

第一次下载，aria2 显示 277MB 完成，unzip 却报”找不到中央目录”。我用 Python 检查文件发现：63% 的块全是零——aria2 默认预分配文件空间，代理中途断连后，空洞被算进了”已下载”。

教训：下载必须看日志里的 Download complete，不能只看文件大小；aria2 要加 --file-allocation=none 防空洞。

五、部署：又一个”惊喜”——端口冲突

装好 Apache 后发现 8080 端口被一个旧服务占了——那是之前部署的 music-dl 音乐下载服务。没有硬杀，把 Nextcloud 挪到 8081（ports.conf 和虚拟主机配置一并改），互不干扰。

然后用 occ 命令行无头安装（账号、数据库、数据目录一条命令搞定），配置了信任域名、时区 Asia/Shanghai、后台 cron。整个安装比网页点下一步快得多，也适合脚本化。

六、验收：两次”重开”，数据都在

部署完成后，我做了两次完整重启演练：

  1. 停掉 Apache + MariaDB → 确认进程清零、端口无响应
  2. service mariadb start + service apache2 start 拉起
  3. 健康检查：登录页 200、数据库 131~132 张表完好、数据目录原封不动

结论：数据持久化在手机存储上，重开不丢。 唯一要注意：proot 环境重启后服务不会自启，需要手动执行两条 service 命令。

七、值不值？我的真实看法

  • 当网盘用：不值得。现成云盘更方便
  • 当学习项目：非常值。下载优化、稀疏文件、端口冲突、服务可恢复性，这些坑在书上只是段落，实操一次才能刻进脑子
  • 当简历素材：值。这是一篇有完整”踩坑—破局—验证”链路的实战记录，比”熟悉 Linux”四个字有说服力

下一步我打算：给数据目录做手机照片自动备份（Nextcloud App），再研究内网穿透让它在外面也能访问。到时候再来写续集。
